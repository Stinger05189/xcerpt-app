# Xcerpt v1.6.0 Specification: Zero-Hitch Foundation & Curation Architecture

> **Document Version:** 1.6.0-SPEC  
> **Status:** Architecture Approved / Ready for Implementation  
> **Target Release:** v1.6.0  
> **Prerequisites:** Xcerpt v1.5.0 Production Baseline

---

## 1. Executive Summary & Problem Space

In Xcerpt v1.5.0, core file staging operations and UI reactivity suffered from architectural anti-patterns that led to UI hitches, memory creep, operating system file locks, and cross-root rule pollution.

Xcerpt v1.6.0 re-engineers the outbound curation pipeline to achieve **zero-hitch performance**, strict **multi-root isolation**, and a **predictable, safe file handle lifecycle**. This milestone establishes the robust architectural foundation necessary for the bidirectional v2.0 LLM Dev Studio.

### Core Objectives:

1. **Eliminate Background Disk Thrashing:** Replace eager, debounced `fsSync` payload generation with an in-memory virtual graph and a Just-In-Time (JIT) physical export machine with clear visual readiness states.
2. **Isolate Multi-Root Rules:** Scope exclusions, inclusions, and tree-only rules strictly to individual root paths via composite keys (`${rootId}::${relativePath}`), ending unintentional cross-root rule collisions.
3. **Eradicate Operating System File Locks:** Enforce strict read-only file handle lifetimes with guaranteed `try/finally` release patterns in Node.js IPC routines.
4. **Overhaul Export Configuration:** Replace arbitrary multi-chunk batch sliders with a binary export mode (`All Files` vs `Single Unified context.md`) and transform the flat chunk table into a virtualized, hierarchical **Payload Preview Tree** showing true skip-deducted sizes and live tokens.
5. **Modernize Tab & Selection Workflows:** Implement VS Code-style transient (preview) versus pinned tabs, mouse-wheel and right-click drag tab overflow scrolling, global multi-root ephemeral packaging, and pencil skip-block badges on tree rows.
6. **Descriptive Manifests with In-Line Skill:** Standardize manifest naming to `Xcerpt_Manifest_<Roots>.md` and provide an optional toggle to embed the strict Code Generation Protocol (`Skill_code_generation_protocol.md`) directly into prompt exports.

## 2. Subsystem 1: The Zero-Hitch Virtual Staging Engine

### 2.1. Root Cause Analysis of v1.5.0 Freezes

In v1.5.0, `MainStage.tsx` attached an auto-build effect to every state change:

```typescript
// Anti-Pattern in v1.5.0:
useEffect(() => {
  if (!isStale || rootPaths.length === 0) return;
  const timer = setTimeout(async () => {
    const payload = generateExportPayload(...);
    const generatedPaths = await window.api.stageExport(payload);
    setExportState({ isStale: false, isBuilding: false, chunkPaths: generatedPaths });
  }, 1500);
  return () => clearTimeout(timer);
}, [isStale, ...]);
```

This triggered `processExport()` in `main.cjs`, executing synchronous `fsSync.writeFileSync` loops for hundreds of files on the Node.js main thread. If a user was typing in Monaco, toggling exclusions, or brushing marquee selections, the event loop was starved by constant file creation and directory purging in `os.tmpdir()`.

### 2.2. The In-Memory Virtual Payload Graph

In v1.6.0, background disk staging is completely removed:

- When curation rules, compressions, or root paths mutate, Xcerpt recalculates an **In-Memory Payload Graph** within a Web Worker or non-blocking microtask.
- The graph tracks:
  - Virtual file manifests (relative paths, flat output names, active skip counts).
  - True skip-deducted byte sizes.
  - Estimated and exact BPE token counts.
  - Formatted Markdown File Tree strings.
- **Disk I/O during curation is exactly zero.**

```
[User Toggles Rule / Skip] ──> [Update Zustand Store]
                                        │
                                        ▼ (Non-blocking)
                           [Compute Virtual Graph in RAM]
                                        │
             ┌──────────────────────────┴──────────────────────────┐
             ▼                                                     ▼
    [Update Tree & UI Preview]                             [Invalidate JIT Cache]
    (Instant, 0ms Disk Overhead)                           (Flag isStaged: false)
```

### 2.3. Dual-State JIT Staging State Machine

To guarantee that native OS drag-and-drop (`webContents.startDrag`) and clipboard copies receive 100% valid, intact files without race conditions, staging follows a two-tier state machine:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        STATE MACHINE: JIT STAGING                      │
├───────────────────┬────────────────────────────────────────────────────┤
│ State             │ Characteristics & Invariants                       │
├───────────────────┼────────────────────────────────────────────────────┤
│ 1. VIRTUAL_READY  │ - Payload graph is calculated and rendered in UI.  │
│                   │ - Zero physical files exist on disk.               │
│                   │ - Buttons display: "Package Context" or "Copy".    │
├───────────────────┼────────────────────────────────────────────────────┤
│ 2. STAGING_LOCK   │ - User clicks "Stage" or initiates onDragStart.    │
│                   │ - Main process writes files synchronously to       │
│                   │   timestamped directory in os.tmpdir() (~15ms).    │
│                   │ - UI displays a spinner: "Staging Payload...".     │
├───────────────────┼────────────────────────────────────────────────────┤
│ 3. DISK_READY     │ - Physical files verified on disk.                 │
│                   │ - Button transforms into green pill:               │
│                   │   "Ready: Drag Context" or "Copied to Clipboard".  │
│                   │ - startDrag is enabled with absolute file paths.   │
└───────────────────┴────────────────────────────────────────────────────┘
```

#### JIT Invalidation Rules:

Any subsequent mutation to includes, excludes, tree-only flags, or Monaco skip blocks instantly reverts the state machine from `DISK_READY` back to `VIRTUAL_READY`, marking the previous physical cache for deferred garbage collection.

## 3. Subsystem 2: Multi-Root Scoped Curation Engine

### 3.1. The Cross-Root Pollution Problem

In v1.5.0, presets maintained flat arrays of relative paths:

```typescript
// Legacy v1.5.0 Preset Schema:
interface Preset {
	inclusions: string[]; // e.g. ["src/index.ts"]
	exclusions: string[]; // e.g. ["src/utils/api.ts"]
	treeOnly: string[]; // e.g. ["package.json"]
}
```

In a multi-root workspace (e.g., `Root A: /apps/web` and `Root B: /services/auth`), both roots contain `src/index.ts`. Marking `src/index.ts` as excluded in Root A caused Root B's file to be matched and excluded simultaneously.

### 3.2. Scoped Composite Key Architecture

v1.6.0 refactors the rule schema so every file-level curation rule is bound to a specific root identifier:

```typescript
// v1.6.0 Scoped Rule Representation:
export type ScopedPathKey = `${string}::${string}`; // Format: "${rootId}::${relativePath}"

export interface ScopedPreset {
	id: string;
	name: string;
	inclusions: ScopedPathKey[];
	exclusions: ScopedPathKey[];
	treeOnly: ScopedPathKey[];
	compressions: Record<ScopedPathKey, CompressionRule[]>;
	history: ExportHistory[];
}
```

#### Key Formatting & Normalization:

- **`rootId`**: Stable hash or canonical path identifier of the root directory.
- **`relativePath`**: POSIX-normalized relative path within that root (e.g., `src/utils/api.ts`).
- **Global Rule Exemption:** Only directory-name blacklists (`hardBlacklist`: `node_modules`, `.git`, `dist`) remain global across all roots.

### 3.3. Status Evaluation Resolution (`filterEngine.ts`)

The filter resolution engine receives the active `rootId` during tree traversal:

```typescript
export function getScopedFileStatus(
	rootId: string,
	relativePath: string,
	isDirectory: boolean,
	includes: ScopedPathKey[],
	excludes: ScopedPathKey[],
	treeOnly: ScopedPathKey[],
): FileStatus {
	const scopedKey: ScopedPathKey = `${rootId}::${normalizePath(relativePath)}`;

	// 1. Root-scoped Exclusions override everything
	if (excludes.includes(scopedKey)) return "excluded";

	// 2. Root-scoped Tree-Only overrides export inclusion
	if (treeOnly.includes(scopedKey)) return "tree-only";

	// 3. Root-scoped Inclusions
	if (includes.length > 0) {
		if (isDirectory) return "included";
		if (!includes.includes(scopedKey)) return "excluded";
	}

	return "included";
}
```

## 4. Subsystem 3: Read-Only Safety & File Lock Eradication

### 4.1. File Handle Audit in `main.cjs`

To prevent Xcerpt from locking user files (causing external editors like VS Code, Git, or compilers to fail with `EBUSY` or `EPERM`), all Node.js file operations must guarantee that file descriptors are immediately closed.

#### Fixed Binary Check Implementation:

```javascript
ipcMain.handle("fs:readFile", async (_, filePath) => {
	let fh = null;
	try {
		const stats = await fs.stat(filePath);
		if (stats.size > 5 * 1024 * 1024) {
			throw new Error(
				`File exceeds 5MB limit (${(stats.size / 1048576).toFixed(2)} MB). Preview disabled.`,
			);
		}

		// Open file handle with explicit read-only flag
		fh = await fs.open(filePath, "r");
		const buffer = Buffer.alloc(4096);
		const { bytesRead } = await fh.read(buffer, 0, 4096, 0);

		// Scan for null-byte binary signatures
		for (let i = 0; i < bytesRead; i++) {
			if (buffer[i] === 0) {
				throw new Error("Binary file detected. Preview disabled.");
			}
		}

		// Read full UTF-8 contents
		return await fs.readFile(filePath, "utf-8");
	} finally {
		// Guarantees handle release even on exceptions
		if (fh) {
			await fh.close();
		}
	}
});
```

### 4.2. Chokidar Non-Locking Configuration

On Windows, Chokidar can place persistent directory locks. `main.cjs` is updated with `useFsEvents: false` and `usePolling: false` optimizations, ensuring that watcher handles do not block external file deletions, branch checkouts, or IDE operations.

## 5. Subsystem 4: The Payload Preview Tree & Staging Overhaul

### 5.1. Deprecation of Arbitrary Multi-Chunk Sliders

AI chat interfaces (Claude, ChatGPT) now accommodate monolithic context files or flat batch uploads. The arbitrary "Batch Size Limit" slider (2–50 files) is eliminated in favor of an unambiguous binary configuration:

1. **`All Files (Flattened Batch)`**: Exports all files as separate flat files (`<Root>_<Path>.ext`) plus the manifest tree file.
2. **`Single Unified (context.md)`**: Combines the manifest tree and all file contents with code fences into a single structured markdown document.

### 5.2. Hierarchical Payload Preview Tree

The flat HTML chunk table in `ExportStage.tsx` is replaced by a high-density, virtualized **Payload Preview Tree**:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ Payload Preview Tree                                     [ ] Single Unified context.md │
├───────────────────────────────────────────────────────┬──────────┬───────────┬─────────┤
│ Name                                                  │ Tokens   │ True Size │ Actions │
├───────────────────────────────────────────────────────┼──────────┼───────────┼─────────┤
│ ▼ src/                                                │ ~14,200  │ 48.2 KB   │         │
│   ▼ components/                                       │ ~8,400   │ 28.5 KB   │         │
│       TreeNode.tsx                                    │ ~2,100   │ 6.8 KB    │ [-] [x] │
│       ContextEditor.tsx  [3 skips] ✏️                 │ ~1,850   │ 5.2 KB    │ [-] [x] │
│     App.tsx                                           │ ~1,200   │ 4.1 KB    │ [-] [x] │
│   ► utils/                                            │ ~5,800   │ 19.7 KB   │         │
│   package.json [-]                                    │ ~320     │ 1.1 KB    │ [A] [x] │
└───────────────────────────────────────────────────────┴──────────┴───────────┴─────────┘
```

#### Tree Column Specifications:

- **Left Column (Hierarchy):** Expand/collapse chevrons, file/folder icons, relative path, skip indicators (`[3 skips]`), and the edit pencil badge.
- **Token Column:** Exact BPE token counts for files; aggregated recursive token counts for folders.
- **True Size Column:** Physical size minus skipped lines:
  $$\text{TrueSize} = \text{FileSize} \times \left(\frac{\text{TotalLines} - \text{SkippedLines}}{\text{TotalLines}}\right)$$
  Folder rows display the aggregate true size of all contained files.
- **Inline Action Buttons:**
  - `[-]` (Tree-Only): Keeps file in the manifest tree for LLM spatial awareness, but omits code body from export.
  - `[x]` (Exclude): Excludes file entirely from export and tree.
  - `[A]` (Include): Restores an excluded or tree-only file to full export.
- **Filter & Search Bar:** Real-time text filtering with quick toggles: `[Show Tree-Only]`, `[Show Excluded]`, `[Show Skipped]`.

## 6. Subsystem 5: Tab Lifecycle & UI Ergonomics

### 6.1. VS Code-Style Transient vs. Pinned Tabs

To prevent tab bar clutter when navigating large file trees:

- **Transient (Preview) Tab:**
  - Triggered by a **single click** on a tree node.
  - Title displays in _italics_.
  - Opening another file in transient mode reuses the same tab.
- **Pinned Tab:**
  - Triggered by a **double click**, pressing **`Enter`** on a row, or editing a skip block.
  - Title displays in regular text.
  - Pinned tabs persist side-by-side until explicitly closed.
- **Tab Context Menu:**
  - Right-clicking any tab opens a portal context menu: `Close`, `Close Others`, `Close to the Right`, `Close All`, `Copy Relative Path`, `Reveal in OS Explorer`.

### 6.2. Tab Bar Overflow Handling

In `MainStage.tsx`, the tab container is enhanced to support:

- **Horizontal Mouse-Wheel Scrolling:** `onWheel` listener translating vertical delta to horizontal scroll (`scrollLeft += deltaY`).
- **Right-Click Drag Scrolling:** Holding right-click and dragging horizontally sweeps the tab container smoothly.
- **Fixed Action Controls:** The right-hand action container (`Stage Context`, `Configure`, `Zoom`) is pinned with `shrink-0 z-30` and a subtle backdrop blur, preventing buttons from compressing during tab overflow.

### 6.3. Skip Block Feedback in Tree Nodes

In `TreeNode.tsx`, files with defined skip blocks display a colored pencil icon (`✏️` / `Edit3`, 12px) adjacent to the filename. Hovering reveals a tooltip: `3 skip blocks active (-140 lines)`.

## 7. Subsystem 6: Multi-Root Ephemeral Selection & Preset Ergonomics

### 7.1. Unified Multi-Root Ephemeral Packaging

Ephemeral selections now bridge across roots seamlessly:

- Selected files from Root A and Root B are tracked in a unified selection set.
- Clicking the primary **`[Package Context]`** button generates an ephemeral package containing files from all active roots, disambiguating identical root folder names automatically.
- Next to `[Package Context]`, a secondary **`[Preview]`** button opens the **Payload Preview Tree Overlay** limited to the selected files.
- Individual historical cards in the sidebar will no longer include redundant `[Package Context]` buttons; clicking a past history card simply restores that selection set to the active tree.

### 7.2. Preset Duplication

The preset management dropdown in `Sidebar.tsx` adds two actions:

1. **`Duplicate Preset (From Existing)`**: Deep-clones the active preset (inclusions, exclusions, tree-only rules, skip blocks) under a new name.
2. **`Create Preset from Selection`**: Generates a new preset where only the currently highlighted files are included, and all other visible files are excluded.

### 7.3. Live Sidebar Statistics

The mock statistics in `Sidebar.tsx` are wired to real-time computed data:

- **Total Included Files:** Live count across active roots.
- **Estimated / Exact Tokens:** Reactive sum of all included source code and manifest lines.
- **Saved via Skips:** Live calculation of tokens/bytes saved via Monaco skip annotations.

## 8. Subsystem 7: Descriptive Manifest Naming & In-Line Protocol

### 8.1. Canonical Manifest Naming

Generic `ExportedFileTree.md` filenames are replaced with descriptive names reflecting the workspace roots:

- Single Root: `Xcerpt_Manifest_<RootName>.md`
- Multi-Root: `Xcerpt_Manifest_<Root1>_<Root2>.md` (e.g., `Xcerpt_Manifest_Client_Server.md`)

### 8.2. In-Line Protocol Injection

In the export configuration pane, an optional checkbox is added:

- **`[x] Embed Code Generation Protocol in Manifest`**
- When checked, Xcerpt appends the exact rules of the `Skill_code_generation_protocol.md` directly into the generated markdown manifest header:
  - Instructions on `### Pre-Code Summary`.
  - Line 1 action tags (`// [NEW]`, `// [MODIFIED]`, `// [DELETED]`).
  - Natural structural anchors.
  - Standardized skip markers (`// ... [Skipped: N lines] ...`).
- This primes the receiving LLM to respond in diff-ready, machine-parsable format without requiring external developer prompt setup.
