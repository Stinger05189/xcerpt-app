# 6_v2.0_DevStudio_Refinements_Spec.md

# Xcerpt v2.0 Refinements Specification: Workspace-Scoped Dev Studio & Ingestion Triage Engine

> **Document Version:** 2.0.1-SPEC  
> **Status:** Architecture Approved / Ready for Implementation  
> **Target Release:** v2.0.0 Final  
> **Prerequisites:** Session 026 Baseline

---

## 1. Executive Summary & Problem Space

Session 026 successfully established the Monaco Diff Merge editor, manual buffer editing, single-action rollback, and syntax highlighting across web, systems, and game development languages (including Lua and shaders). However, testing revealed key architectural friction points in session containment, navigation, and initial packet ingestion:

1. **Global vs. Workspace Session Contamination:**
   - The entry point was split across the global TitleBar and the MainStage header.
   - The studio currently mounts as a full-screen window overlay (`fixed inset-0 z-50`), obscuring the TitleBar tabs and preventing users from seeing which workspace is active or switching workspaces while in a session.
   - Session state was partially shared globally, causing sessions to appear across unrelated workspaces.
2. **Ingestion Modal Focus Trap & Lack of Pre-Triage Inspection:**
   - In clean workspaces without existing sessions, the raw markdown paste textarea could become unclickable due to overlay focus traps and backdrop pointer-events conflicts.
   - Developers were forced to paste raw markdown into a blind textarea with no real-time syntax feedback, file boundary inspection, or error recovery before committing to a session.
3. **Multi-Location Reasoning & Markdown-in-Markdown Resilience:**
   - LLMs frequently emit reasoning commentary not only at the start of a work packet, but also between code blocks and at the end of files.
   - Target files that are themselves Markdown (`.md`, `.mdx`) containing embedded code blocks can cause boundary confusion if fence depth and inner artifact boundaries are not visually delineated.

## 2. Subsystem 1: Workspace-Scoped Dev Studio Architecture

### 2.1. Single Workspace-Relative Entry Point

- Remove the Dev Studio icon from the top TitleBar entirely.
- The **only** entry point into the Dev Studio will be the button located in `MainStage.tsx` adjacent to `Stage Context` and `Configure`:
  ```
  [Stage Context]  [Dev Studio (X Pending)]  [Configure]
  ```
- This button directly reflects the state of the **currently active workspace**. If an ongoing session exists for this workspace, it shows a badge with the pending file count.

### 2.2. Preserving Core TitleBar Accessibility

- Refactor `DevStudioModal.tsx` so that it is positioned below the application TitleBar (`top-10 inset-x-0 bottom-0` or embedded within `MainStage.tsx`):
  - The application TitleBar remains 100% visible, active, and draggable.
  - Users can click workspace tabs in the TitleBar to switch between workspaces instantly.
  - When switching back to a workspace with an active dev session, the studio reappears exactly where the user left off.
- The dev session state is indexed strictly by `workspaceId`:
  ```typescript
  // sessionStore.ts
  sessionsByWorkspace: Record<string, DevSession | null>;
  activeSessionIdByWorkspace: Record<string, string | null>;
  ```

## 3. Subsystem 2: Interactive Ingestion Triage Studio

Instead of a plain modal with a simple textarea, the ingestion experience transforms into an **Interactive Ingestion Triage Studio**:

````
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ INBOUND LLM RESPONSE TRIAGE                                [Paste from Clipboard] [x]  │
├─────────────────────────────────────┬──────────────────────────────────────────────────┤
│ EXTRACTED ACTIONS & TRIAGE (3)      │ RAW RESPONSE EDITOR & FILE BOUNDARY MAP          │
│                                     │ Search: [ filter... ]       [Re-Parse Response]  │
│ [MOD] src/auth/token.ts          ✓  ├──────────────────────────────────────────────────┤
│       14 lines • TypeScript         │ # [WORK PACKET 1]: Auth Rotation                 │
│                                     │ Here is the plan to rotate symmetric tokens...   │
│ [NEW] scripts/player.lua         ✓  │                                                  │
│       48 lines • Lua                │ ╭─── FILE BOUNDARY 1: src/auth/token.ts ────────╮│
│                                     │ │ ```typescript                                 ││
│ [!]   docs/spec.md               ⚠  │ │ // src/auth/token.ts                          ││
│       Missing Line 1 Path Header    │ │ export const rotate = () => {};               ││
│                                     │ │ ```                                           ││
│                                     │ ╰───────────────────────────────────────────────╯│
│ [Parse Status: 3 Files / 1 Warning] │ Now we introduce the Lua movement script:        │
│ [Initialize Dev Session Studio]     │ ...                                              │
└─────────────────────────────────────┴──────────────────────────────────────────────────┘
````

### 3.1. One-Click "Paste from Clipboard"

- The initial view provides a prominent `[Paste from Clipboard]` button that directly reads `navigator.clipboard.readText()`.
- Upon pasting, the view instantly renders the split-pane triage interface.

### 3.2. Left Pane: Live Action & Error Manifest

- Displays a real-time list of all extracted actions:
  - Action badge (`[NEW]`, `[MOD]`, `[DEL]`).
  - Target relative path and detected language.
  - Warning badges for heuristic recoveries (e.g. unclosed fences, missing line-1 headers, no-op identical files).
- Clicking any action immediately scrolls the right-hand raw editor to the corresponding file boundary.

### 3.3. Right Pane: Searchable Raw Editor with Visual File Boundaries

- A full-featured editor (Monaco or syntax-highlighted textarea) displaying the complete LLM markdown stream.
- Injected visual boundary rulers or decorations marking where Xcerpt identified opening fences, file headers, and closing fences.
- If a model omitted a fence or mangled a path, the developer can edit the raw text directly in this pane and click **`[Re-Parse Response]`** to immediately recalculate the extracted actions.
- Primary CTA: **`[Initialize Dev Session Studio]`** commits the triaged actions into the active workspace session.

## 4. Subsystem 3: Multi-Location Reasoning & Markdown Resilience

### 4.1. Non-Contiguous Reasoning Trace Association

- LLMs often interleave commentary:
  - _Pre-Code Summary_ (before file 1).
  - _Implementation Details_ (between file 1 and file 2).
  - _Testing Instructions & Next Steps_ (after file 2).
- The parser must associate:
  - Preamble prose $\to$ preceding action(s).
  - Interstitial prose $\to$ succeeding action(s).
  - Epilogue prose $\to$ general session wrap-up section.
- In the Diff Studio, the Reasoning Drawer displays the specific prose block linked to the current file, while providing tabs to read the overall preamble or post-implementation instructions.

### 4.2. Markdown Files Wrapped in Code Fences

- When an LLM outputs an action for a `.md` or `.mdx` file, the file's internal code blocks (e.g. ` ```bash `) must be guarded using outer 4-backtick or 5-backtick fences.
- The triage view and diff editor must properly recognize the inner file content as Markdown without treating inner backticks as closing boundaries.
