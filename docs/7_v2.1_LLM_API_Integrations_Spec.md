# Xcerpt v2.1.0 Specification: Provider-Agnostic LLM Integration & Copilot Automation

> **Document Version:** 2.1.0-SPEC  
> **Status:** Architecture Approved / Ready for Implementation  
> **Target Release:** v2.1.0  
> **Prerequisites:** Xcerpt v2.0.0 Baseline (Bidirectional Dev Studio & Ingestion Triage Engine)

---

## 1. Executive Summary & Problem Space

With the completion of Xcerpt v2.0.0, the desktop context staging and bidirectional response triage pipelines are fully functional offline. However, developers still face two repetitive manual friction points:

1. **Manual Session Labeling & Description Writing:**
   When pasting long, complex LLM work packets into the Ingestion Triage Studio, the developer must either manually type a session title and description or rely on heuristic regex fallbacks that can produce generic names.
2. **Manual Git Commit Message Construction:**
   Upon completing a dev session and merging file actions into the workspace, developers must draft a commit message manually, cross-referencing changed files, diffs, and project commit conventions.

**Xcerpt v2.1.0 introduces Xcerpt's first native LLM API integration layer.** Designed to be modular, secure, and provider-agnostic, the system defaults to **OpenRouter** utilizing **`google/gemini-3.5-flash-lite`**, leveraging native structured JSON schema enforcement (`response_format`) and tool calling capabilities.

## 2. Subsystem 1: Provider-Agnostic LLM Client Architecture

### 2.1. Core Interfaces (`src/features/llm/types/llm.ts`)

```typescript
export type LLMProviderId = "openrouter" | "gemini" | "openai" | "anthropic";

export interface LLMMessage {
	role: "system" | "user" | "assistant";
	content: string;
}

export interface LLMToolFunction {
	name: string;
	description: string;
	parameters: Record<string, unknown>; // JSON Schema object
}

export interface LLMToolDefinition {
	type: "function";
	function: LLMToolFunction;
}

export interface LLMCompletionOptions {
	model: string;
	messages: LLMMessage[];
	temperature?: number;
	maxTokens?: number;
	responseFormat?: {
		type: "json_object" | "json_schema";
		json_schema?: {
			name: string;
			strict?: boolean;
			schema: Record<string, unknown>;
		};
	};
	tools?: LLMToolDefinition[];
	toolChoice?:
		| "auto"
		| "none"
		| { type: "function"; function: { name: string } };
}

export interface LLMCompletionResult {
	content: string;
	toolCalls?: Array<{
		id: string;
		name: string;
		arguments: Record<string, unknown>;
	}>;
	usage?: {
		promptTokens: number;
		completionTokens: number;
		totalTokens: number;
		cost?: number;
	};
}

export interface LLMProviderConfig {
	id: LLMProviderId;
	name: string;
	apiKey: string;
	baseUrl: string;
	defaultModel: string;
	availableModels: string[];
}
```

### 2.2. OpenRouter API Integration Contract

Adheres to OpenRouter's Chat Completions API standard:

- **Endpoint:** `POST https://openrouter.ai/api/v1/chat/completions`
- **Headers:**
  - `Authorization: Bearer $OPENROUTER_API_KEY`
  - `Content-Type: application/json`
  - `HTTP-Referer: https://github.com/Stinger05189/xcerpt-app`
  - `X-Title: Xcerpt Dev Studio`
- **Default Model:** `google/gemini-3.5-flash-lite`

#### Request Payload Structure:

```json
{
	"model": "google/gemini-3.5-flash-lite",
	"messages": [
		{
			"role": "system",
			"content": "You are Xcerpt's development assistant..."
		},
		{ "role": "user", "content": "..." }
	],
	"response_format": {
		"type": "json_object"
	},
	"temperature": 0.2,
	"max_tokens": 500
}
```

#### Error Handling Strategy:

- **`401`:** Invalid or missing API key $\to$ Prompt user to open Settings and configure their API key.
- **`402`:** Insufficient OpenRouter credits $\to$ Informative notification with link to `https://openrouter.ai/settings/keys`.
- **`429`:** Rate limited $\to$ Exponential backoff retry (up to 3 attempts).
- **`502`:** Upstream provider generation failure $\to$ Non-blocking UI notice allowing manual entry without blocking workflow.

## 3. Subsystem 2: Secure Credential & Provider Management

### 3.1. Security Architecture

API keys must never be committed, exposed to telemetry, or written to plain unencrypted workspace JSON files:

1. **Storage Location:** Keys are stored in `config.json` inside the OS user data directory (`app.getPath('userData')/XcerptSessions/config.json`).
2. **IPC Isolation:** The renderer process interacts with LLM providers exclusively through the Electron main process via guarded IPC (`llm:complete`), preventing network interception or malicious script injection into Chromium.

### 3.2. Settings Modal Configuration (`SettingsModal.tsx`)

A new dedicated **LLM Integrations** section is added to Global Preferences:

- **Provider Selector:** Dropdown offering `OpenRouter (Default)`, `Google Gemini API`, `OpenAI`, `Anthropic`.
- **API Key Input:** Masked password field with toggleable show/hide button and validation indicator.
- **Model Selector:** Dropdown populated with provider models (default: `google/gemini-3.5-flash-lite`), plus an `[+ Add Custom Model]` input.
- **Connection Test Action:** A `[Test Connection]` button executing a minimal ping query (`max_tokens: 5`) to verify credentials immediately.

## 4. Subsystem 3: Session Creation Copilot (Naming & Description)

### 4.1. The Zero-Code Payload Rule

**[IMMUTABLE DIRECTIVE] To maximize speed, minimize token consumption, and protect user privacy, the Session Creation Copilot MUST NEVER include raw file bodies in prompt payloads.**

Naming a session requires understanding architectural intent, not scanning thousands of lines of syntax. The context payload is strictly minimal:

```
[Parsed LLM Reasoning Traces]
- Preamble Intent
- Interstitial file commentary
- Work packet headers

[File Action Manifest]
- [NEW] src/plugins/renderer_svg/templates.lua
- [MODIFIED] src/plugins/renderer_svg/cache.lua
- [DELETED] src/legacy/old_raster.lua
```

### 4.2. JSON Schema & Prompt Contract

#### System Prompt:

```text
You are Xcerpt's Session Naming Assistant. Given an LLM work packet's architectural intent and a list of target file actions, generate a concise, human-readable session title (under 50 characters) and a clean, 1-2 sentence description summarizing the architectural goal.

You MUST respond strictly with valid JSON conforming to the schema:
{
  "title": string,
  "description": string
}
```

#### User Context Payload:

```json
{
	"intent": "Migrate SVG rasterization to asynchronous Promises and add LRU cache.",
	"actions": [
		{ "type": "NEW", "path": "src/plugins/renderer_svg/templates.lua" },
		{ "type": "MODIFIED", "path": "src/plugins/renderer_svg/cache.lua" }
	]
}
```

#### UI Integration in `IngestionTriageStudio.tsx`:

- In the top-left metadata panel, adjacent to the Title and Description inputs, render an **`[AI Generate (Gemini 3.5)]`** button with a `Sparkles` icon.
- Clicking the button initiates an animated loading state.
- Upon completion, the inputs are populated with the model's structured output. The developer retains full ability to edit or refine the text prior to initializing the session.

## 5. Subsystem 4: Session Completion Commit Synthesizer

### 5.1. Context Assembly Pipeline

When all file actions in a session are merged or reviewed, the developer can generate a high-fidelity commit message. To ensure adherence to project conventions, Xcerpt constructs a targeted context packet:

1. **Session Architectural Intent:** The session description and preamble commentary.
2. **File Actions Manifest:** Exact list of modified, created, and deleted files.
3. **Physical Git Diff:** Captured via `git diff --staged` or per-file hunks across the target roots (truncated to a safe limit of 5,000 tokens).
4. **Recent Git Commit History:** The last 5 commit subjects obtained via `git log -5 --oneline` to align with the repository's commit style (e.g. Conventional Commits, emoji prefixes, imperative tense).

### 5.2. JSON Schema & Prompt Contract

#### System Prompt:

```text
You are Xcerpt's Git Commit Assistant. Generate a conventional, production-ready Git commit message based on the architectural intent, file actions, diff summary, and the repository's recent commit style.

You MUST respond strictly with valid JSON conforming to the schema:
{
  "subject": string,
  "body": string
}
```

#### UI Integration in `DevStudioModal.tsx`:

- Inside the Git Commit Dialog and on the `SessionCompleteBanner`, provide an **`[AI Synthesize Message]`** button.
- The model's output fills the commit message textarea formatted with a standard conventional commit subject and bulleted structural change body:

  ```text
  feat(renderer): implement asynchronous SVG rasterization and caching

  - Add templates.lua with NanoSVG XML generator routines
  - Refactor cache.lua to use deterministic seed hashing
  - Prune obsolete synchronous rasterization logic
  ```

- The developer can edit the message and click `[Commit Changes]` to execute the commit via IPC.
